# Kimi K2 on NVIDIA GB10

This note records the sanitized result of the Kimi K2 qualification on a
128 GiB NVIDIA GB10 system. Raw prompts, completions, captures, and machine
paths are intentionally excluded. This is an experimental branch result, not
an upstream-supported profile.

## Result

Kimi-K2-Instruct was converted to a 361.63 GiB VQ3R WARP container. The model
reports 1.026 trillion parameters in total and 31.69 billion active per token:
61 MLA layers, 384 routed experts, and top-8 routing.

The final matched check used three prompt families, 64 generated tokens per
run, one fresh CPU reference and two fresh CUDA runs per family:

| Measure | CPU fallback | Selected CUDA profile |
| --- | ---: | ---: |
| Mean decode throughput | 1.223 tok/s | **2.748 tok/s** |
| Best observed run | 1.227 tok/s | **3.001 tok/s** |
| Mean speedup | — | **2.25x (+124.8%)** |

The selected CUDA profile used:

```text
expert cache: 73728 MiB
total server budget: 84783939744 bytes
router lookahead: 6
readers / queue depth: 2 / 2
compute: 8 threads, compute-only CPUs 5-9,15-19
idle policy: child-scoped PM QoS Q0
I/O and cache: direct I/O, LFRU
arithmetic: Q8 on; SDOT and I8MM off
WASTE_CUDA_KDA=1
WASTE_CUDA_DENSE=3
WASTE_CUDA_VQ=2
WASTE_CUDA_VQ_GROUP=1
WASTE_XPAR=0
```

K2 has no KDA layers; `WASTE_CUDA_KDA=1` remains the existing Q4 selector and
records zero KDA calls here. The K2 allowlist makes that no-KDA composition
legal only for the exact qualified geometry.

## Correctness gates

Across 195 causally compared steps:

- generated tokens, argmax, top-10 ordering, and ordered routes were unchanged;
- route replacements and CUDA fallbacks were zero;
- dense and VQ call counters matched their precomputed values;
- the worst maximum absolute logit difference was `4.9114e-5`;
- the VQ3R expert apply itself remained byte-exact.

The dense fast path is therefore not bit-identical at every logit. Its stated
contract is unchanged greedy output and routing, bounded numerical error, and
no fallback—not a claim of byte-identical dense arithmetic.

## Resident soak

One resident server completed 24 requests and 4,608 generated tokens over four
deterministic cycles. Repeated outputs had identical SHA-256 hashes. There were
no request failures, restarts, swap reads or writes, CUDA errors, or post-warm
RSS growth; maximum GPU temperature was 67 C. Median end-to-end throughput,
including prefill, was 1.860 tok/s.

## Scope and caveats

- The CUDA path fails closed unless the complete K2 fingerprint and VQ3R
  geometry match. VQ4P and unqualified shapes remain rejected.
- The qualified K2 container supports raw `/v1/completions`. WARP does not
  interpret its Jinja template, and the container has no supported `chat.json`,
  so `/v1/chat/completions` remains unavailable.
- Lookahead 4 was about 0.5% slower while reading roughly 8-10% fewer expert
  bytes; it is a reasonable lower-traffic alternative.
- This branch does not change the existing qualified K3 profile.
